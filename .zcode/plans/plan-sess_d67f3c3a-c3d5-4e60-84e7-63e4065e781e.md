# 探测策略优化：用可接受的探测次数，最大化版本发现

## 现状诊断（成本模型）
当前 smart 模式总请求 ≈ 历史区全量盒 + 前沿。前沿里**广撒网是最大的固定开销**：
- `sparseMajorCandidates` 生成最多 **60** 个候选主版本，每个用 `majorEntryProbes` 的 **5** 个入口形状探测，`probeParallel(..., stop=0)` **无条件全发** → **最多 300 次探测**，且对绝大多数"不存在的主版本"也照样发满 5 次。
- 入口形状 `{0,0},{0,1},{1,0},{1,1},{2,0}` 里 `{1,1}` 作为"主版本首发"极罕见，纯浪费。
- 副版本维度**没有撒网**：`scanDim(buildMinor,...)` 连续 `frontStop`(5) 个空 minor 就永久停止 → 跳号的 minor（如 0,1,2,9,10，锚点在 2）永远探不到 9+。

历史区全量枚举是发现主干（稀疏老版本靠它），保留。

## 改动（都在 `frontier.go`）

### 1. 广撒网入口按候选"早停"探测（主要结构改动，成本大降）
把当前"把所有候选的所有入口堆成一个批处理 `probeParallel(stop=0)`"改为**逐候选探测、首个命中即认为该主版本存在并跳到下一候选**：
- 新增 `f.probeMajorExists(M, P) bool`：顺序探 `majorEntryProbes(M)` 的入口，任一命中返回 true（早停）。
- `run()` 里遍历 `sparseMajorCandidates`（已按距锚点升序），对每个候选调 `probeMajorExists`，命中即加入 `majorHits`。
- 加预算护栏：累计探测超过阈值（约 `capCount×3`）或 `isAborted` 即停止遍历，保证不会失控。
- **效果**：已存在的主版本只花 1 次（而非 4~5 次）；全空时上限受护栏约束。并发度靠入口探测本身仍是轻量 HEAD，整体墙钟可接受。

### 2. 入口形状精简（5→4）
`majorEntryProbes` 去掉 `{1,1}`，保留 `{0,0},{0,1},{1,0},{2,0}`（覆盖绝大多数主版本首发形态），发现基本不变。

### 3. 候选上限 60→45，并收紧远端噪声
- `sparseMajorCandidates` 的 `capCount` 60→45。
- 5/10 倍数撒点仅在锚点主版本较大（≥20）时启用（小锚点下这些是噪声）；年份带保留（年份式版本需要）。

### 4. 副版本撒网（补发现，新能力）
对锚点主版本 + 每个撒网命中的主版本，在稠密 `scanDim` minor 扫描后追加一轮**稀疏 minor 探测**，抓"跳过 frontStop 间距"的 minor：
- 新增 `f.sparseMinorProbe(M, knownMinors) []int`：在 `lastKnownMinor` 之后、`hi[1]` 之内，按近端步长2 + 少量远点撒一小批（受小预算约束，约 ≤8 个），用早停式探测，命中的 minor 返回。
- `run()` 把返回的 minor 并入 `minorHits`，后续补丁填充自然覆盖它们的 patch。
- **效果**：0,1,2,9,10 这类 minor，锚点 2 时也能探到 9/10。成本每主版本 +约 3~8 次。

## 成本/收益预期（smart，P=3，稀疏发布）
- 广撒网：300 → 约 45~120（早停 + 精简 + 上限）。
- 副版本撒网：+约 (命中主版本数 × 3~8)。
- 净效果：**总前沿成本下降约 40~60%**，同时**补上跳号 minor 的发现**，主版本发现能力不降。

## 验证
1. 本地 mock 复现三种场景：①跳号 minor（0,1,2,9,10）；②主版本首发非 X.0.0（如只有 X.1.0）；③稀疏发布。
2. 对比改前/改后：请求数 + 命中集合（命中应 ≥ 改前，请求数应明显更低）。
3. `go build` / `go vet` / `go build -race` + race 跑一遍（0 DATA RACE）。
4. 回归之前已验证的 autoclaw / manus / ZCode 场景不劣化。

## 不做的事
- 不动历史区全量枚举（发现主干，保留）。
- 不引入跨 OS/扩展名替换到版本探测（那是 `-platform` 职责，避免请求爆炸）。
- 不改 `-path-variants` 默认行为。
